# SILENT CODE - محاسبة المصنع

برنامج محاسبة تصنيع وتغليف وبيع (عطور)، مبني بـ React + Vite، متصل بـ
Firebase (Firestore + Authentication + Storage)، ومنشور عبر Vercel.

## الرابط الحي
https://silent-code-swart.vercel.app

## الخدمات المستخدمة (3 خدمات، كلها مجانية)

| الخدمة | الرابط | الوظيفة |
|---|---|---|
| **GitHub** | github.com/silentcodeofficial/silent-code | يخزّن الكود المصدري لكل ملفات البرنامج |
| **Vercel** | vercel.com → مشروع silent-code | يبني وينشر الموقع تلقائيًا من GitHub، يعطي الرابط الحي الثابت |
| **Firebase** (Google) | console.firebase.google.com → مشروع silent-code-oman | Firestore (قاعدة البيانات) + Authentication (تسجيل الدخول) + Storage (ملفات مرفقات الفواتير) |

## هيكل الملفات

```
├── src/
│   ├── App.jsx          ← البرنامج كامل (كل الواجهات والتبويبات والحسابات)
│   ├── firebase.js       ← الاتصال بـ Firebase (قاعدة بيانات + دخول + تخزين ملفات + نسخ احتياطية)
│   └── main.jsx           ← نقطة دخول React (ثابت، نادرًا يتغيّر)
├── firestore.rules       ← قواعد أمان قاعدة البيانات (تُحدَّث من Firebase Console)
├── storage.rules         ← قواعد أمان تخزين الملفات (تُحدَّث من Firebase Console)
├── package.json          ← قائمة المكتبات المستخدمة
├── index.html, vite.config.js, .gitignore  ← إعدادات أساسية ثابتة
```

## طريقة أي تحديث مستقبلي
1. يُعدَّل `src/App.jsx` و/أو `src/firebase.js` (وأحيانًا `package.json` لو أضيفت مكتبة جديدة)
2. تُحدَّث بواجهة GitHub: حذف الملف القديم → Upload files → رفع الجديد بنفس الاسم بالضبط
3. Vercel ينشر تلقائيًا خلال دقيقة إلى دقيقتين
4. لو التحديث يخص قواعد الأمان (`firestore.rules` أو `storage.rules`)، يُحدَّث من Firebase Console مباشرة، **مو من GitHub**

## دروس مهمة تعلمناها (لتفادي تكرارها)
- **دائمًا تحقق من توازن التعليقات** (`/*` مقابل `*/`) بالكود قبل الإرسال — تعليق ناقص الإغلاق مرة سبّب حذف 5 دوال كاملة من البرنامج بصمت تام بدون أي خطأ وقت البناء
- **لا تكتفِ بفحص الكود بعينك** — ابنِ نسخة تجريبية فعلية (`vite build`) وتأكد الدوال المطلوبة موجودة فعليًا بالناتج النهائي قبل إرسال أي تحديث
- **احذر تكرار تحميل نفس اسم الملف** — المتصفح يضيف أرقام مثل `(1)`, `(2)` تلقائيًا، وهذا يسبب رفع ملف بالاسم الغلط على GitHub (يصير ملف منفصل غير مستخدم بدل ما يستبدل القديم)
- بعد أي تحديث لـ `package.json`، البناء بـ Vercel ياخذ وقت أطول شوي (تثبيت مكتبات جديدة)

## المميزات الحالية الكاملة
- تسجيل دخول حقيقي بإيميل وكلمة مرور (Firebase Authentication)، كل شريك بحسابه الخاص
- إدارة المخزون والمواد الخام بمتوسط تكلفة مرجّح يتحدث تلقائيًا مع كل شراء
- تسجيل المشتريات مع: تكاليف إضافية موزّعة (بترول، فندق...)، دعم الدرهم الإماراتي بتحويل تلقائي، رقم فاتورة/اسم مورد/ملاحظات لكل مادة على حدة، ترقيم تسلسلي للمشتريات
- **مرفقات فواتير الشراء**: تصوير/رفع فاتورة المورد، تضغط وتتحول PDF تلقائيًا، تُخزَّن بـ Firebase Storage (منفصل عن قاعدة البيانات)، تظهر بتبويب "سجل المشتريات" مع فلترة بالتاريخ
- المنتجات والوصفات (تصنيع كامل أو تغليف منتج جاهز) بأسماء عربي/إنجليزي، وأكواد مرجعية تلقائية
- دفعات الإنتاج الفعلية مع تكلفة تاريخية دقيقة، ومنع بيع كميات أكبر من المتوفر فعليًا
- فواتير بيع بخصومات (لكل صنف أو للفاتورة كاملة)، هدايا مجانية، طباعة احترافية عربي/إنجليزي، تتبع توصيل/استلام
- تتبع استهلاك مواد إضافية (مثل الأكياس) لكل فاتورة بيع، بدون ظهورها للعميل، لمعرفة المتبقي بالمخزون
- إدارة العملاء (بحث، سجل مشتريات، حذف، تعديل اسم)
- التسويق والسامبلات، خسائر التصنيع، المعدات والأصول الثابتة (بأرقام مرجعية قابلة للتعديل)، تكاليف التأسيس
- تقارير أرباح لكل منتج، توزيع الأرباح على الشركاء بنسب قابلة للتعديل
- نسخة احتياطية يدوية (تحميل/استعادة JSON) + نسخة احتياطية تلقائية يومية صامتة داخل قاعدة البيانات (بدون حذف تلقائي، تتراكم للأبد)
